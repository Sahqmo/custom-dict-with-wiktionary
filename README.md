# Personal Wiktionary — 프로젝트 인수인계 문서

다른 환경(Claude Code 세션 포함)에서 이어서 작업할 수 있도록 정리한 문서입니다. 이 파일과 `scripts/download.py`만 옮기면 됩니다.

## 1. 목표

Glosbe처럼 **거의 모든 언어의 단어를 검색**할 수 있는 **개인용 오프라인 사전**을 만든다.

- 설명 언어는 **영어로 고정** (English Wiktionary 기반).
- **"번역 쌍" 구조는 피한다.** A언어 단어 → B언어 대응어 목록이 아니라, 단어 자체의 **영어 정의(gloss)·어원·발음·활용형·관련어**를 보여주는 사전으로 만든다. Wiktionary의 translation 표는 기본 화면에서 빼고, 필요하면 접어서 보는 옵션으로만 둔다.
- 개인용이므로 **로컬 서버로 돌려도 되고**, React 같은 구조로 정돈해도 된다.
- 라이선스: Wiktionary 내용은 CC BY-SA. 개인용이어도 화면 하단에 출처 표기를 넣는다.

## 2. 결정된 사항

- 데이터 출처: **kaikki.org의 Wiktextract JSONL** (영어판 Wiktionary를 이미 구조화한 파일).
  - 영어판 공식 XML 덤프(`enwiktionary-latest-pages-articles.xml.bz2`, 약 1.6GB)는 위키텍스트 템플릿을 직접 파싱해야 하므로 **쓰지 않는다.** (kaikki 데이터에 빠진 부분을 확인할 때만 선택적으로 받는다.)
  - 참고로 사용자가 처음 가리킨 `de.wiktionary.org/wiki/Wiktionary:Download`는 **독일어판**이라 정의가 독일어다. 영어 설명 조건에 맞지 않아 영어판/kaikki 주소를 쓴다.
- 저장소: **SQLite (FTS5)**. 전 언어를 담으면 데이터가 수 GB라서 브라우저에 통째로 올릴 수 없다.
- 구조: `kaikki JSONL → ingest 스크립트 → dictionary.sqlite → API 서버 → React UI`
- 기본 스택(아직 확정은 아님, 선호가 없으면 이대로 진행): **Node(Fastify) + React + Vite + TypeScript**. ingest만 Python으로 하고, 전부 Node로 통일할 수도 있다.

## 3. 현재 상태

| 단계 | 상태 |
|---|---|
| 설계 | 완료 |
| `scripts/download.py` (다운로드 스크립트) | 작성 완료 |
| 데이터 다운로드 | 완료 (`data/raw/raw-wiktextract-data.jsonl.gz`, 약 2.98GB) |
| JSONL 구조 확인 | 완료 |
| ingest 스크립트 / DB | 완료. `scripts/ingest.py` → `data/dictionary.sqlite` (**18.29GB**, 약 15분). entries 10.86M / senses 12.76M / forms 85.65M / relations 16.71M |
| API 서버 (`server/`, Fastify + better-sqlite3) | 완료: 검색, 항목, 정의 역검색(FTS), 언어 목록 |
| React UI (`web/`, Vite) | 최소 버전 완료: 검색, 언어별 그룹, 항목 페이지, 정의 검색 탭, 다크 모드, 출처 표기 |
| 즐겨찾기 / 기록 / 자동완성 / 랜덤 / 자주 쓰는 언어 | 완료 (아래 "구현 메모" 참고). 즐겨찾기·기록은 읽기 전용 단어 DB와 별도로 `data/user.sqlite`에 저장 |

### 실행 방법

```
python scripts/ingest.py            # 최초 1회 (data/dictionary.sqlite 생성)
python scripts/patch_db.py          # (옛 DB를 이미 갖고 있을 때만) 검색 개선용 데이터 덧붙이기 — 서버를 끄고 실행
cd web && npm i && npm run build    # UI 빌드
cd ../server && npm i && npm start  # http://127.0.0.1:3000 (빌드된 UI도 같이 서빙)
```

UI 개발 중에는 `server`를 띄운 채 `web`에서 `npm run dev`를 실행한다 (`/api`는 3000으로 프록시).

Windows에서는 `start.bat`(UI 빌드 + 서버 실행)과 `dev.bat`(저장하면 서버 자동 재시작 + UI 핫 리로드, http://127.0.0.1:5173)을 쓸 수 있다.

### 구현 메모

- **검색 동작** (`server/src/queries.ts`): 정확 일치 → 정규화 일치 → 활용형 → 접두사 순. 언어/품사 필터는 SQL 안에서 건다(예전에는 LIMIT 뒤에 걸러서 `stra`+독일어가 0개였다). 접두사는 뜻이 많은(`entries.weight`) 단어를 먼저 보여 준다. 언어를 고르지 않은 1~2글자 검색은 수백만 행을 훑어야 해서 접두사 단계를 건너뛴다. 독일어 전사(`Haeuser`→`Häuser`)는 결과가 없을 때, 또는 독일어 필터에서 한 번 더 시도한다.
- **DB 패치** (`scripts/patch_db.py`): 이미 만든 DB에 `entries.weight`(뜻 개수), `(lang_code, norm_word)` 인덱스, `langs` 테이블(언어별 항목 수), 리다이렉트 목적지(`relations.type='redirect'`)를 덧붙인다. 재적재 없이 약 2~3분. 최신 `ingest.py`는 처음부터 같은 구조로 만든다. 서버는 이 열/테이블이 없는 옛 DB에서도 동작한다(느릴 뿐). 패치 전에 서버를 끌 것.
- **자동완성** (`GET /api/suggest`): 타이핑 130ms 후 요청. 같은 철자(대소문자·악센트 변형 포함)는 정규화한 철자로 묶고, 여러 언어에 걸치면 "N개 언어"로 보여 주며 선택 시 검색 결과 페이지로 간다(한 언어면 바로 항목 페이지). 자동완성에서는 접두사 일치를 활용형 일치보다 앞에 둔다. 조작: ↑↓ 선택, Enter 이동, Esc 닫기. 어디서든 `/` 를 누르면 검색창으로 포커스(입력 중인 `/`는 그대로 글자).
- **즐겨찾기 · 최근 본 단어** (`#/library`, `server/src/userdb.ts`): `data/user.sqlite`(git 제외)에 저장하므로 브라우저를 바꿔도 유지된다. 항목 페이지의 별 버튼으로 즐겨찾기, 항목을 열면 기록에 자동 기록(최대 1,000개). API: `GET/PUT/DELETE /api/favorites`, `GET/POST/DELETE /api/history`. 화면은 낙관적으로 먼저 갱신하고 서버 호출이 실패하면 서버 상태로 다시 맞춘다.
- **자주 쓰는 언어** (설정): 검색 결과/자동완성에서 같은 일치 단계 안에서 먼저 보이고(`prefer` 파라미터), 언어 선택 목록 맨 위에 나오며, 랜덤 단어도 이 언어들에서 뽑는다. 브라우저 `localStorage`에 저장(최대 10개).
- **랜덤 단어** (`GET /api/random`): 항목 id가 연속이라는 점을 이용해 임의의 id 이후 첫 조건 일치 항목을 집는다(전체 정렬/집계 없이 ~1ms). 뜻이 3개 이상이고 활용형(`form_of`/`alt_of`)이 아닌 항목만. 영어처럼 큰 언어는 언어 인덱스를 막아(`+lang_code`) id 순으로 훑는다 — 인덱스를 타면 150만 건을 정렬해 1초 넘게 걸렸다.
- **`weight`(인기 지표)**: 활용형/대체 표기 뜻(`form-of`/`alt-of` 태그)은 세지 않는다. 독일어 형용사 활용형 항목은 뜻 줄이 10개씩이라 세면 활용형이 원형(`Haus`)보다 위로 올라온다. `patch_db.py`의 `weight_v` 로 버전 관리.
- **표기가 다른 링크 해결** (`getEntry`): 연관어 링크는 장음/강세 표시가 붙은 표기(라틴어 `amō`, 러시아어 `сло́во`)를 쓰는데 항목 표제어는 표시 없는 문서 제목(`amo`, `слово`)이라서 정확 일치만으로는 "항목이 없습니다"가 나왔다(표본에서 끊긴 링크의 라틴어 96%, 러시아어 95%). 정확 일치가 없으면 같은 언어에서 정규화한 철자(`norm_word`)로 찾아 가장 뜻이 많은 표제어를 돌려주고, 화면은 주소를 실제 표제어로 바꾼다(`location.replace`).
- **`useAsync`의 요청 키**: 결과에 deps 키를 붙여, 요청이 바뀐 즉시 이전 데이터를 쓰지 못하게 한다. 예전에는 새 단어로 이동한 첫 렌더에서 "이전 단어의 데이터"를 새 결과로 착각할 수 있었다(리다이렉트/기록 판단에 쓰면 엉뚱한 곳으로 되돌아감).
- **리다이렉트 항목** (`soft-redirect`, 17만 개: 간체 `单词`→번체 `單詞` 등): 뜻 없이 목적지만 가진다. 목적지가 하나면 항목 페이지가 자동으로 따라가고(`location.replace`), 여러 개면 칩으로 보여 준다.
- `norm_word` 정규화 규칙은 `scripts/ingest.py`의 `normalize()`와 `server/src/normalize.ts`가 **같아야** 한다. 바꾸면 DB를 다시 만들어야 한다.
- kaikki의 `etymology_text`에는 "Etymology tree" 계통도 줄이 앞에 붙어 있어 `server/src/queries.ts`에서 걷어낸다.
- **굴절표 엔진** (`server/src/tables/`): `forms`의 태그 조합으로 표를 조립한다. `engine.ts`는 언어를 모르고, 언어/품사별 표 정의(행·열·필수 태그)는 `specs.ts`에 선언한다. 단어 수 상위 10개 언어 중 굴절이 있는 9개 언어의 동사·명사·형용사를 지원한다 — 독일어·스페인어·프랑스어는 `specs.ts`, 영어·라틴어·이탈리아어·포르투갈어·러시아어·스웨덴어는 `langs/*.ts` (중국어는 굴절이 없어 대상이 아님). 새 언어는 `langs/` 아래에 같은 형태의 파일을 만들고 `specs.ts`의 `SPECS`에 등록하면 된다(먼저 `forms`의 태그를 실제로 확인할 것 — 언어마다 태그 이름과 조합이 다르다). 표에 들어가지 않은 형태는 `forms`(그 밖의 형태)로 남는다.
  - 엔진 옵션(`TableSpec`): `group`(접이식 묶음: 라틴어 능동/수동), `exclude`(이 태그가 붙은 형태는 표에서 제외: 러시아어 옛 표기 `dated`), `dedupeStress`(강세 부호만 다른 중복 제거), `preferSingle`, `lemmaCell`, `article`, `morph`. `canonical` 태그(표제어 자신의 표기)는 어디에도 표시하지 않는다.
  - 데이터 특성: 라틴어 형용사의 여격·탈격 복수는 한 형태에 세 성 태그가 같이 붙어 있어 성 태그를 `ignore`로 둔다(각 칸이 자기 성을 필수로 요구하므로 섞이지 않음). 러시아어 속격·여격·조격·전치격 남성/중성도 같은 방식. 이탈리아어/스웨덴어 형용사에는 `error-unrecognized-form`이라는 데이터 오류 태그가 섞여 있어 무시한다. 포르투갈어 인칭 부정사(falar, falares…)는 별도 표.
  - **어미 강조**(`morph`)는 9개 언어 모두 지원한다. 불규칙 형태는 "단어 전체가 굴절 부분"이라는 뜻이라 어미와 같은 방식(포인트 컬러 볼드)으로 보여 준다(데이터는 `m:'e'`/`m:'i'`로 구분해 두지만 스타일은 같다). 방식이 두 가지다:
    - 독일어·스페인어·프랑스어: 부정사에서 어간을 구한다(`deMorph`/`esMorph`/`frMorph`) + 언어별 정규 어미 목록으로 불규칙 판정.
    - 영어·라틴어·이탈리아어·포르투갈어·러시아어·스웨덴어: 같은 표/행의 형태들이 공통으로 시작하는 부분을 어간으로 삼는다(`stemMorph`, `pairMorph`). 부정사에서 어간이 안 나오기 때문이다(라틴어 `rēx`→`rēgis`, 러시아어 `сло́во`→`слова́`). 동사는 시제(행)마다 "전부가 공유하는 앞부분", 없으면 다수결(60%); 격 변화표는 표 전체에서 다수결(70%, 3군 명사 주격 `rēx`처럼 일부가 어간이 다른 경우 때문). 2글자 미만 어간은 의미가 없어 불규칙로 본다. 같은 칸의 대체형(수축형 `amāstī` ← `amāvistī`)은 어긋난 지점부터를 어미로 본다. 영어는 정규 어미 목록(`-s -es -ed -ing -er -est …`)으로 `make → made`, `go → gone` 같은 우연한 앞부분 일치를 불규칙로 거른다.
    - 비교 시 무시하는 결합 기호(`FOLD`): 라틴어 장음, 이탈리아어 강세·개폐 표시, 러시아어 강세 부호. 원문 표기는 그대로 두고 어간을 찾을 때만 접는다.
  - 정관사(`article`)는 독일어·스페인어·프랑스어·이탈리아어·포르투갈어 명사.
  - `formPattern`: 러시아어 표는 키릴 문자 형태만 받는다(같은 태그로 섞인 로마자 전사 `idjá` 제외).
  - 셀 매칭: 형태의 태그가 (필수 태그 ⊆ 형태 태그 ⊆ 필수 태그 ∪ ignore) 이면 그 셀에 들어간다. `rare`/`obsolete`/`before-vowel` 등은 위치 태그가 아니라 셀 안의 비고로 표시한다.
  - 발음기호가 활용형처럼 섞인 항목(프랑스어 `paʁl`)은 걸러낸다.
  - **정관사** (`articles.ts`): 명사의 성은 `head` 문자열("Haus n (...)")에서 읽는다(`parseGenders`). 독일어는 성×격×수, 스페인어는 el/la/los/las(강세 a로 시작하는 여성 명사는 IPA 강세로 판별해 `el agua`), 프랑스어는 le/la/l'/les. 프랑스어 `h` 시작 단어는 묵음/유음 h를 IPA로 구분할 수 없어 `le/l'`로 병기한다(ingest에서 "aspirated h" 카테고리를 보존하면 해결 가능).
  - **어미 강조** (`morph.ts`): 어간(부정사에서 어미를 뗀 것)으로 시작하고 나머지가 언어별 정규 어미 목록(`*_ENDINGS`)에 있으면 어미만 `m:'e'`, 아니면 단어 전체를 불규칙 `m:'i'`로 표시한다. 스페인어/프랑스어 미래·조건법은 부정사 기준(행에 `axInf`). 독일어는 분리동사(`gehe auf`), 과거분사(`ge-…-t`), `-eln/-ern`의 e 탈락을 따로 처리한다. `bin gegangen` 같은 복합시제는 조합이라 강조하지 않는다. 설정에서 끌 수 있다(`data-hl`).
  - 한계: "어간으로 시작하는 불규칙"은 어미 목록으로만 거른다(예: `tengo`는 잡지만 어미가 우연히 목록과 같은 불규칙은 규칙형으로 보일 수 있다). 새 언어를 추가할 때 `*_ENDINGS`를 같이 정의해야 한다.
- **디자인 토큰 / 설정 페이지** (`web/src/index.css`, `settings.ts`, `SettingsPage.tsx`, 경로 `#/settings`): 색은 CSS 변수(토큰)로만 쓴다. 포인트 컬러는 라이트/다크를 따로 저장(`localStorage`의 `settings.v1`)하고 `--accent-l`/`--accent-d`로 주입하며, 파생색(`--accent-soft` 등)은 `color-mix()`로 계산한다. 포인트 컬러 위 글자색은 대비를 계산해 흰색/검정 중 자동 선택한다. 설정 미리보기는 `data-scheme` 속성으로 해당 모드 토큰을 강제해 실제 페이지와 같은 스타일로 그린다.
- **홈 헤드라인의 돌아가는 "word"** (`web/src/RotatingWord.tsx`): 36개 언어의 "단어"를 5초마다 슬라이드로 교체한다(`INTERVAL_MS`). 단어 목록은 같은 파일의 `WORDS`에 추가/수정하면 된다(언어 코드·한국어 이름·원어 이름 포함. 마우스를 올리거나 키보드 포커스가 가면 단어 위에 `독일어 · Deutsch` 같은 언어 이름이 페이드로 나타나고, 한국어 이름은 스크린리더용 이름에도 쓰인다). **DB에 실제 항목이 있는 단어만 넣을 것** — 단어를 클릭하면 그 항목 페이지(`#/entry/{코드}/{단어}`)로 이동한다. 글자가 잘리지 않도록 슬라이드 상자(`.rw-clip`)는 글자 폭보다 좌우 `0.12em`, 위아래 `0.14em` 넓게 잡았다(벵골어·데바나가리·베트남어는 글자 폭 밖으로 0.07em까지 삐져나온다). 표기와 표제어가 다르면 `entry`로 지정한다(간체 `单词` → 번체 `單詞`). 마우스를 올리거나 포커스가 있는 동안은 넘어가지 않는다. 조사 `를`은 고정이라 외국어 단어 뒤에서는 발음에 따라 어색할 수 있다. `prefers-reduced-motion`에서는 애니메이션 없이 바뀐다.
- **포인트 컬러에서 파생되는 색** (`settings.ts`의 `partnerColor`, `index.css`): 
  - `--accent-2`(짝 색)는 포인트 컬러를 OKLCH로 바꿔 밝기·채도는 유지하고 색상만 돌려 만든다(노랑~연두 40~110°는 -45°, 그 밖은 +50°: 초록→청록, 청록→파랑, 인디고→분홍, 앰버→코랄). 예전에는 모든 포인트 컬러를 고정 분홍(`#ec4899`)과 sRGB로 섞어서 보색에 가까운 초록·청록·라임·앰버의 그라데이션 끝이 탁한 회갈색이 되었다.
  - `--accent-soft`/`--accent-line`/`--ring`은 `color-mix(in oklab, …)`로 섞는다(sRGB에서 섞으면 선명한 초록이 회색빛으로 탁해진다).
  - `--accent-ink`는 연한 포인트 배경 위에 올리는 글자색(포인트 컬러를 글자색 쪽으로 15% 섞음). 알약 글자 대비가 라이트에서 Blue 4.35·Green 4.21·Amber 4.23이던 것을 5.2 이상으로 올렸다. 연한 배경 위에 포인트 컬러 글자를 새로 올릴 때는 `--accent`가 아니라 `--accent-ink`를 쓸 것.
- **홈 헤드라인의 움직이는 그라데이션** (`App.css`의 `.grad`): `@property`로 각도(`--g-angle`)와 두 색의 위치(`--g-a`, `--g-b`)를 보간 가능한 값으로 등록하고, 서로 다른 주기(11s/7s/9s)의 키프레임으로 흘린다(주기가 맞물리지 않아 같은 모양이 좀처럼 반복되지 않는다). 색 A는 -50%~38%, 색 B는 62%~150%에서 움직이고 둘 사이 간격은 항상 24%p 이상이라 두 색이 항상 글자 안에 보인다. 각도는 55°~160°. `prefers-reduced-motion`에서는 정지.
- **UI 언어** (설정 > 언어, `web/src/i18n.ts` · `locales.ts`): 한국어/English/日本語/中文/Deutsch/Français/Español/Esperanto. 화면에 보이는 문구(버튼, 안내, placeholder, aria-label, 문서 제목)만 바꾸고, 사전 내용(정의·어원·굴절표의 문법 용어·언어 이름 데이터)은 영어 Wiktionary 그대로다. 브라우저 `localStorage`의 설정(`locale`)에 저장하고 기본값은 한국어다.
  - `ko`가 기준이고 나머지 7개 언어는 같은 키를 **빠짐없이** 가져야 한다 — 타입(`Record<MessageKey, string>`)으로 강제해서 키가 하나라도 빠지면 컴파일이 실패한다. 새 문구는 `ko`에 키를 만들고 7개 언어를 채운 뒤 `t('키', { n: 3 })`로 쓴다. 문구는 모듈 로드 때 한 번 계산하지 말고 렌더할 때 `t()`를 호출할 것(그래야 언어를 바꾸면 바로 반영된다 — `MATCH_KEYS`, `REL_KEYS` 참고).
  - 단수/복수 변화를 피하려고 "결과 n개" 대신 "결과: n" 꼴을 쓴 곳이 있다. 홈 헤드라인은 언어마다 어순이 달라 `hero.pre/post/grad/rest` 네 조각으로 나눠 회전 단어 앞뒤에 끼운다(한국어의 조사 `를`도 여기).
  - 날짜·상대 시간은 `Intl`로, 회전 단어 라벨의 언어 이름은 `Intl.DisplayNames`로 UI 언어에 맞춘다(브라우저가 모르는 언어는 영어로 대신 — 에스페란토는 보통 영어로 나온다). `<html lang>`을 바꿔 한·중·일 글리프와 스크린리더 발음이 맞게 한다(`index.css`의 `html[lang='ja'|'zh']` 글꼴 스택).
- 파일 이름 주의: Windows는 대소문자를 구분하지 않으므로 `settings.ts`와 `Settings.tsx`처럼 대소문자만 다른 파일을 만들면 TS 빌드가 깨진다.
- DB가 예상(3~8GB)보다 큰 주원인은 `forms`(8,500만 행)다. 줄여야 하면 ingest에서 forms/relations를 줄이고 다시 만든다.

## 4. 다른 환경에서 해야 할 일

### 4.1 다운로드

환경: Python 3.12 (표준 라이브러리만 사용), 디스크 여유 20GB 이상 권장.

```
python scripts/download.py
```

- `data/raw/raw-wiktextract-data.jsonl.gz` (약 3GB)가 생긴다. URL은 `https://kaikki.org/dictionary/raw-wiktextract-data.jsonl.gz` (HTTP 200 확인됨).
- 끊기면 `.part` 파일에서 이어받는다. 이미 완료된 파일은 건너뛴다.
- `--dump`(영어판 XML 덤프)와 `--all`은 **지금은 필요 없다.**

### 4.2 이 PC로 가져오기

다운로드한 `raw-wiktextract-data.jsonl.gz`를 이 프로젝트의 `data/raw/` 아래에 복사한다. (또는 다른 환경에서 ingest까지 끝내고 `dictionary.sqlite`만 가져와도 된다.)

## 5. 다음 단계 (다운로드 완료 후)

원본 파일 전체를 대화나 콘솔에 출력하지 말고, 스크립트로 스트리밍 처리한다. 구조 확인은 앞쪽 몇 줄만 본다.

1. **데이터 확인**: JSONL 앞부분 몇 줄과 필드 구조를 확인한다. 항목 하나는 한 줄의 JSON이며, `word`, `lang`, `lang_code`, `pos`, `senses`, `forms`, `sounds`, `etymology_text` 등을 가진다. (필드 이름은 raw 데이터라 실제 파일로 확인할 것)
2. **ingest 스크립트** (`scripts/ingest.py` 예정): gz를 스트리밍으로 읽어 SQLite에 적재한다. 쓰지 않는 필드는 버려 크기를 줄인다.
3. **API + 최소 UI**: 검색과 항목 페이지부터 만든다.
4. **부가 기능**: 역방향(정의로 찾기) 검색, 즐겨찾기, 오디오 등.

## 6. DB 스키마 초안

- `entries(id, word, norm_word, lang_code, lang, pos, etymology, ...)`
- `senses(entry_id, gloss, tags, examples)`
- `sounds(entry_id, ipa, audio_ref)`
- `forms(entry_id, form, norm_form, tags)`: 활용형에서 원형으로 연결
- `relations(entry_id, type, target)`: 동의어, 파생어, 하위어 등
- `norm_word` / `norm_form`: 검색용 정규화 키 (소문자화, 발음 구별 기호 제거, 한글 자모 분해 등)
- **FTS5** 가상 테이블: 영어 정의 텍스트 역방향 검색용

## 7. 검색/UI 동작 설계

- 검색 순서: 표제어 정확 일치 → 정규화 일치 → 접두사 일치. 활용형에 맞으면 원형 항목으로 안내한다.
- 같은 철자가 여러 언어에 있으면 **언어별로 묶어서** 보여준다. 언어 필터와 품사 필터를 둔다.
- 항목 페이지: 품사별 정의, 어원, IPA와 오디오, 활용형 표, 관련어 링크.
- 정의 텍스트로 찾는 역방향 검색(FTS)은 별도 탭.
- 기록, 즐겨찾기(서버 쪽 SQLite 테이블에 저장), 다크 모드.

## 8. 예상 규모와 주의점

- **오늘의 단어** (`/api/daily`, `dailyEntries`): 홈의 예시 칩 6개. 날짜(사용자 로컬 YYYY-MM-DD)를 시드로 한 난수라 같은 날은 같은 단어이고 자정에 바뀐다. 자주 쓰는 언어가 있으면 언어마다 1개, 없으면 서로 다른 6개 언어에서 1개씩.
- **동사 표 뒤집기** (`TableSpec.transpose`): 동사 표는 시제를 열, 인칭을 행으로 출력한다. 어미 강조는 뒤집기 전에 계산한다.
- **자동 굴절표** (`server/src/tables/auto.ts`, `AUTO_LANGS`): 설계도가 없는 언어도 태그를 차원(격/수/인칭/시제…)으로 분류해 표로 만든다. 서법·태·부정 등은 표를 나누는 기준, 나머지는 가능한 행/열 배치를 점수로 비교해 고른다. 어미 강조·관사는 없다. 현재 핀란드어·네덜란드어만 켜 두었다. 터키어는 원본 동사 태그가 어긋나(인칭 오류, 한 칸에 형태 다수) 제외했다.
- **연관어 안내 문구 필터** (`REL_POINTER`): 데이터에 섞인 "see Thesaurus:…" 같은 안내 문구는 응답에서 뺀다.
- 최종 SQLite는 필드를 줄이면 대략 3~8GB로 예상한다. (실측 전 추정치)
- ingest는 한 번 돌리는 데 수십 분에서 1시간 정도를 예상한다. 스트리밍 처리라 메모리는 크게 필요 없다.
- 데이터 갱신은 새 덤프를 받아 DB를 다시 만드는 방식으로 한다.
